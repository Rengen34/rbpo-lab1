# Проверка безопасности v2 — учебный API закупок

Дата: 2026-09-19. Область: новые 25 HTTP-маршрутов варианта 24 и их влияние на приложение первой работы. Ориентир: [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/releases), актуальная стабильная версия на дату проверки. Это ограниченная проверка учебного локального сервиса, не заявление о соответствии ASVS.

## Активы и границы

Активы: исходники, номер билета в настройке и записи пяти ресурсов в памяти. Для проверок используются только вымышленные имена и суммы; реальные закупочные и персональные данные вводить не следует. Секретов, базы данных, файловых загрузок и внешних вызовов у приложения нет.

Точки входа: два старых GET и 25 новых маршрутов с JSON-телами для POST/PATCH. Граница доверия проходит между HTTP-клиентом и привязкой входных полей, затем между сервисом и хранилищем. Роли и учётные записи для входа не реализованы: любой клиент, способный соединиться с сервером, может менять учебные записи. Поэтому сервер должен слушать только `127.0.0.1`; перед публикацией в сеть необходимы аутентификация и авторизация по действиям и объектам.

## Проверяемые риски и меры

| Риск | Решение в этой версии | Проверка / предел |
| --- | --- | --- |
| Подмена серверных `id` и времени через JSON | Входные типы содержат только разрешённые поля, неизвестные поля и явный `null` отклоняются | HTTP-тесты 400 для `id`, `createdAt`, `updatedAt`, `currentTime` и лишнего поля |
| Неверная или отсутствующая ссылка | Сервис проверяет существование записей и соответствие предложения заявке | HTTP-тесты 404/409 и повторное чтение после отказа |
| Висячие ссылки при удалении и гонках | Удаление связанного объекта даёт 409, а все публичные операции сервиса синхронизированы на одном экземпляре | Проверки связанного графа; отдельный нагрузочный тест не выполнялся |
| Раскрытие внутренних ошибок | Ожидаемые ошибки дают короткий JSON без стека вызовов | HTTP-тесты тела ошибок 400/404/409 |
| Доступ из сети | `server.address: 127.0.0.1` в `application.yml` | При живом запуске проверен сокет `127.0.0.1:18080`; адрес не менялся |
| Секреты и уязвимые зависимости | Секреты не нужны; `pom.xml` использует набор зависимостей первой работы | Проверка проекта и прежний анализ 97 точных зависимостей от 2026-09-19 в [v1](security-v1.md); новых зависимостей нет |
| Потеря данных | Хранилище в памяти, перезапуск удаляет записи | Явно указано в руководстве; резервного восстановления нет |

Ограничения: нет входа по паролю, разграничения пользователей, постоянного хранения, ограничения скорости и отдельного лимита размера JSON. Это допустимо для локального учебного примера с вымышленными данными, но не для эксплуатации с настоящими закупками. Чистый анализ зависимостей не доказывает отсутствие уязвимостей. Перед изменением адреса прослушивания или добавлением реальных данных нужен новый обзор доступа, хранения, журналов и восстановления.

Повторяемая проверка: из корня проекта выполнить `.\mvnw.cmd verify`, затем безопасно вызвать маршруты на `127.0.0.1` с вымышленными данными по [инструкции](lab2-guide.md). Ожидаются коды и отсутствие побочного изменения при 400/404/409. Если проверка не проходит, не публиковать новую версию, вернуть файлы к предыдущему коммиту и повторить `verify`.

Фактически 19.09.2026: JDK 21, Maven Wrapper `verify`, 9 тестов, 0 ошибок. Отдельный запуск JAR на порту 18080 подтвердил ответы 200/201/204/409, сохранение полей при PATCH, запрет удаления связанной записи и локальный адрес прослушивания; ещё один запуск на 18082 подтвердил 400 при явном `null` и сохранение десятичной точности. Тесты MockMvc проверили 400/404/409 и все 25 маршрутов. Скан новых текстовых файлов на секреты и нежелательные метки выполнен; найденных секретов нет. Ревью кода, типов входа, связей и обработки ошибок проведено отдельно от реализации; подтверждённых дефектов в указанной области нет. Нагрузочное испытание и проверка устойчивости к специально большим телам не проводились.
